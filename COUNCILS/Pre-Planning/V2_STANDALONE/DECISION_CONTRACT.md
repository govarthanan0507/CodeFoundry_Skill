# Decision Contract — Pre-Planning V2

## Assessment must contain
Input/provenance; inherited purpose/outcome; confirmed value context; necessity; value/context analysis; alternatives/evidence; risks; inherited feasibility implications; progression rationale; uncertainties; progression conditions; upstream return items.

## Decision must contain
Run/version; inherited references; system verdict; decisive evidence; reasoning; unresolved evidence; upstream return target if applicable; Design Council handoff conditions; human authorization status.

## Verdict validity
GO_TO_DESIGN_COUNCIL requires no material product-definition contradiction, no unresolved feasibility blocker, a clear progression rationale, and explicit treatment of remaining uncertainties.

NEEDS_MORE_EVIDENCE requires named decision-changing evidence.

RETURN_TO_PRODUCT_DEFINITION requires a material meaning/scope/outcome/boundary problem.

RETURN_TO_FEASIBILITY requires a material build/operational condition unresolved upstream.

DO_NOT_PROCEED requires evidence supporting stopping, without claiming technical impossibility.

## Anti-repetition
Repeating Feasibility without adding a progression judgment is incomplete. Inventing new technical feasibility conclusions is out of scope.
