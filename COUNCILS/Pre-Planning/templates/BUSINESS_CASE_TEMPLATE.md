# Business Case — Template (Advocate)

Produced by: Advocate role (`roles/Advocate.md`). Always created — see
"Fast-path" below. Never omitted.

## Header (always filled)

- Project / idea reference (`idea.md` link)
- Date
- Path taken: **FULL** or **FAST-PATH**
- If FAST-PATH: reason (same signal named across the other three
  templates for this project)

## Fast-path rule

All sections below are still present. Each is filled with:
`Not argued in full — [reason from Header]. The user-value statement
below is still given in short form, since "why build this at all" is
never skipped, even for a hobby project.`

## Sections (full path)

### 1. Value proposition
Who benefits, what pain is real, why it matters — named specifically
(per `roles/Advocate.md` Rule 1), not "users would love this."

### 2. Strategic alignment / why now
Why this deserves resources now rather than later or never.

### 3. Justification vs. alternatives
What this does that a named existing alternative (per
`MARKET_RESEARCH_TEMPLATE.md` §3) genuinely doesn't — differentiation
claim checked against that research, not asserted independently.

### 4. Financial upside (full path only — commercial intent)
Where relevant: expected revenue/savings, and how it compares to
`FEASIBILITY_REPORT_TEMPLATE.md`'s cost estimate. Skipped with reason on
fast-path or non-commercial projects, not filled with a speculative
number.

### 5. Concessions
Any Skeptic point the Advocate found actually correct, stated plainly
(per `roles/Advocate.md` Rule 3 and its Escalation duty) — a business
case with zero concessions across a real debate is a signal worth
noting, not a clean win by default.
