# Test Matrix — Design Council V2

## Hard invariants
No missing-input pass; preserve product meaning; inherit Feasibility conditions; every capability maps PRD→FRD→TRD; preserve domain concepts; no arbitrary epic count; no technical-layer-only epics; preserve compound capabilities; preserve independent outcomes; explicit ownership for cross-cutting/enabling capabilities; preserve negative scope; coherent V1; PRD reconstructs product; escalate human-owned constraints; distinguish deadlock from infeasible premise; explicit human authorization.

## Adversarial families
Novel semantic domain; workflow; platform; API; data; AI/ML; search/retrieval; recommendation; content/media; creative tool; automation/agentic; marketplace; multi-sided B2B; realtime collaboration; physical+software; migration; existing-code extension; personal/hobby; regulated; security/privacy; compound; tiny; large; cross-cutting; shared enabling; negative scope; lifecycle-heavy; uncertain concept; cost-constrained; scale-sensitive; international; role/permission-heavy; event-driven; offline/local-first; integration ecosystem; monetization-dependent.

## Mutation tests
Genericize a domain concept; hide enabling commitment; add conflicting non-goal; merge independent capabilities; split a compound capability into technical layers; add cross-cutting behavior; add actor/outcome; change feasibility condition; introduce unresolved meaning; remove upstream capability.

Any silent loss or reinterpretation is FAIL.
