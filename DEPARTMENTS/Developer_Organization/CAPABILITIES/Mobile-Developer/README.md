# Mobile Developer

Partially built, honestly labeled — populated in this session, not
fabricated up to false completeness.

- `IDENTITY.md` — real, copied from CodeFoundry's original
  `AGENTS/Mobile/AGENT.md`: mission, ownership boundaries,
  inputs/outputs, handoff format.
- `workflow.md` — built this session: platform technology confirmation
  (Kotlin/Swift native, KMP, Flutter, React Native — per
  `COUNCILS/Design-Council/TECH_REFERENCE_LIBRARY.md`'s mobile
  section), platform-specific structure, device-level security as a
  hard rule, app-store submission readiness, and a deliberately
  minimal build-time smoke check.

**Still missing, by design, not oversight:** a full device-verification
/ QA-style contract. Per an explicit correction this session, deep
testing (device/OS-fragmentation coverage, real-device verification)
belongs to `QA_Organization`, not duplicated as a Mobile Developer
self-check the way Frontend/Backend Developer's own `QA_CONTRACT.md`
files do for their domains — this role's own verification step is
intentionally lighter (Phase 5 of `workflow.md`), not an unfinished
version of a heavier contract still to come.

CodeFoundry's own `SHARED/WORKER_SCOPE_REGISTRY.md` still labels this
capability "BUILT" — that was inaccurate before this session (the
directory was empty) and is now substantively true for the
development side, still intentionally thin on the verification side
per the boundary above.
